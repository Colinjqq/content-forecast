# 审核用户文案与确定视频操作
## 进入条件
用户确认组合选题后，默认请他提供自己编辑的文案。没有稿件时给简短写作要点并等待；用户明确要求代写时才提供完整草稿。不擅自跳过选题确认。
读取档案、概念地图、确认选题与用户文案。保留作者立场、真实经历与表达习惯，先审核，按需要做局部修改。

## 六维审核
严格使用 templates/script-review.md。六个维度都必须作为独立小标题展开，每个标题开头立即给出该项分数，全部采用10分制：

1. 开头力度：是否快速建立问题、冲突、收益或结果承诺。
2. 主题显化程度：观众是否能迅速知道这条内容究竟在讲什么。
3. 个人证据：是否包含用户亲历、数据、案例、实物或可展示结果。
4. 金句排布：关键表达是否出现在需要提神和推进的位置。
5. 观点重复：分数越高表示无效重复越少，信息持续推进。
6. 反馈延迟：分数越高表示新信息、例子、转折或画面反馈出现得越及时。

每项必须引用或定位原文依据，并给出该项最优先的一处修改。最后计算六项算术平均分，保留一位小数；不能凭总体印象另打总分。平均分用于诊断当前稿件，不承诺播放表现。

评分后列出最影响表现的三个问题、建议保留的个人表达、缺少的证据与画面。错别字、病句、口语不顺和可缩短句子放在“顺手修正”，不另设评分项。
材料可为操作结果、具体经历、实物、可信来源、案例与推理。没有证据则补做实验或收窄结论，不能编造经历。

## 下一步动作
每次明确给出结论：补材料 / 改稿 / 可以拍摄 / 定稿后预测。
输出表格“文案位置/具体动作/需拍或录的画面/完成标准”。动作必须具体，如录下输入和输出、并排展示两份结果、删去重复解释、补一句必要前提；不笼统说增强节奏、提高冲击力。
只为实际内容安排镜头、录屏、切换、字幕与必要停顿，不强加花哨特效；标题封面不设独立环节。规定视频操作是给执行清单，不代表Agent已经拍摄或剪辑。
用户发回修改稿后，先简要列出已解决的问题、仍存在的问题、是否可以拍摄和拍摄时必须出现的证据画面。达到可拍摄状态后询问是否需要预测，不直接强行进入预测。

用户选择预测时，请他提供同一账号的过往文案和对应后台数据截图，并补充平台、账号、截图统计时点、是否投流及内容形式。Agent先从材料提取统一记录；无法确定统计窗口的数据标记为未知，不混入正式数值基线。用户说按此定稿即可视为稿件确认。未解决的材料缺口记入预测局限，不虚称成片审核。

## 留档
用户原稿保存为 draft-v1.md；编辑稿与操作表分别存档，保持版本。每条作品保存于 content-forecast-data/items/<id>/。脚本重大修改保留旧版本，不覆盖已锁定快照。
