# Colin 四象限概念地图
## 核心
选题背后是问题。先整理行业问题与概念，再组合出题，选择自己能接住的问题，解决并展示结果。不要默认先刷热点或爆款；热点只是可选输入。

## 两条轴
“我懂不懂” × “其他人懂不懂”。受众和同行统一归为其他人，不拆两张图，也不改成对标是否公开覆盖。
“其他人懂不懂”记录用户对行业的整体判断，不要求所有人一致。不确定则待定，向用户补问，不能假装知道他懂什么。保存判断理由、日期，允许以后调整。

## 四象限
1. 共识区：你懂，其他人也懂。熟悉概念作为理解入口。
2. 盲区：你不懂，其他人懂。标记学习、请教与验证需求。
3. 前瞻区：你不懂，其他人也不懂。探索问题，不能把未知直接写成结论。
4. 金矿区：你懂，其他人不懂。个人知识、经验和信息差。

## 建图
先读 profile.md 和 concept-map.md。没有则从 templates/concept-map.md 建图。
收集行业概念、问题、工作流程、客户提问、成本、渠道和用户经历。AI可以提议候选词，但未经用户确认的认知归属标待定。先用少量真实词跑通，不强制填写庞大问卷。
美妆原例：大牌平替、618购物清单；皮肤科医生、代工厂报价单、演员化妆师；成分党、男性美妆；小样利润率、药妆平均成本、坑位费、返点结构。这些只是原作者特定语境示例，不能永久固定归属。

## 组合生成
- 象限内组合：如金矿区“药妆”+“利润率”，提出可调查的利润结构问题。
- 跨象限组合：如共识区“大牌平替”+金矿区“成本结构”，提出“平替成本一定比大牌低吗？”
- 共识+盲区：从熟悉现象提出需要请教的问题，先补知识。
- 金矿+前瞻：用已掌握的方法设计探索实验，不伪装成已有答案。
组合不局限两词，但必须有真实语义关系；不做无意义笛卡尔积。用户要100条时可分批，去重，并报告有效数量，不保证任意行业都能产出1000条优质选题。
每个结果必须标注组合类型：
- 同象限组合：两个或多个词来自同一区域；
- 跨象限组合：词来自两个或多个不同区域。
同时显示来源概念及象限、组合原因、形成的问题、目标受众为何在意、你能否接住、已有证据和待补工作。默认推荐3个并说明优先项；不按象限直接许诺流量。

## 从问题到内容
先检验：可回答吗？有用吗？有材料吗？能展示结果吗？
有证据才能确定结论；没有则输出采访、学习或最小实验任务。用户确认角度后进入脚本。
增长与获客为目标标签，获客额外核对潜在客户与可交付服务，不能把播放高等同成交高。
把新学会的概念和实践写回地图，记录移动原因。受众定位可据反馈调整，不承诺十万粉丝之前必然有效。

## 新用户建档输出（Colin确认）
仅在没有创作者档案时请用户自我介绍：身份/行业、做过什么、希望吸引谁；对话已有资料不重复问。收到介绍后必须用四个大标题输出：

1. **你的创作者档案**：使用固定表格，至少包含身份与行业、实际做过的事情、可展示案例、当前业务、平台、内容目标、核心盈利受众、重点内容受众、延伸受众、表达特点和待确认信息。三类受众不得擅自合并。
2. **你的核心内容主线**：先写一句“帮助谁 → 解决什么问题 → 使用什么独特经验或方法 → 产生什么结果”，再列最多三条主线。
3. **建议添加或调整的词**：逐词写建议动作、建议象限、原因和仍需证据。随后明确询问用户是否补充、删除、移动或修改。
4. **继续挖掘金矿区的问题**：只问一个结合用户真实经历的问题，格式接近“做X时，有什么是你实际做过以后才发现、外行很容易想错的？”

第三部分是分流点：
- 用户有补充或修改：下一次回复先合并、去重、写入记录，再用 templates/concept-map.md 的四格 Markdown 表完整展示更新后的四象限；末尾询问是否继续调整。用户继续调整则重复本步骤。
- 用户明确没有补充、无需修改或表示直接继续：不得再追问，下一次回复直接生成选题。

用户随时说“补充词汇”“更新身份”“这个我现在懂了”，读取已有档案与概念地图，合并、去重、保留判断理由与变动记录，不整张覆盖。确实写入文件后才说已保存；新会话读取同一内容目录恢复记忆，不承诺跨设备自动同步或模型永久记忆。

## 选题输出
进入选题时，先用一句话解释四个区域对用户的作用：共识区降低理解门槛，金矿区建立差异和信任，盲区指出学习或采访方向，前瞻区适合用实验寻找答案。

选题可以是同象限组合或跨象限组合。每个候选必须显示：
- 选题；
- 组合类型：同象限 / 跨象限；
- 来源词与各自象限；
- 为什么这样组合；
- 适合吸引谁；
- 为什么适合用户讲；
- 需要什么证据。

让用户自行选择，不自动替他完成全文。结尾固定表达其含义：“选择一个选题，接下来完成你的初稿，再把文案发给我，我会审核。”选题得到用户确认后进入审核与视频操作模块。

## 回访用户
回访用户遵循 references/session-routing.md。已有档案和确认象限时，不重新输出四段建档内容；用户未指定任务时只给简短状态和下一步。用户直接提出任务时立即进入对应模块。
